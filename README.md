# Календарь смен — Next.js + Supabase

Обновлённая версия приложения без подписки и лишнего брендинга. В проекте:

- аккаунты Supabase Auth + гостевой режим;
- сохранение профиля, username, аватара, настроек и календаря в БД;
- выход из аккаунта;
- месячный календарь со сменами, доп. сменами, отпусками и выходными;
- отдельные настройки календаря внутри календаря;
- произвольные выходные дни недели;
- графики 5/2, 2/2, 1/3, 3/3, 4/2 и «по дням недели»;
- ручная установка часов на любой день;
- безопасное восстановление прошлых часов при возврате из отпуска/выходного в смену;
- доп. смена: 3500 ₽ или 1 отгул;
- счётчик накопленных отгулов;
- тёмная тема и адаптивность;
- заработок и CSV-экспорт;
- админ-панель с редактированием аккаунтов по ID/username;
- роли user / premium / admin / owner;
- Premium добавляет только удобства кастомизации, не урезая обычных пользователей.

## 1. Установка

```bash
npm install
```

Создайте `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Ссылка на эти значения: Supabase Dashboard → Project Settings → API.

## 2. Создание БД

Откройте Supabase → SQL Editor → New query и вставьте файл:

`supabase/migrations/001_init.sql`

Нажмите Run. Он создаёт:

- `profiles` — профиль, UUID пользователя, username, роль;
- `work_settings` — рабочие настройки;
- `app_settings` — тема и интерфейс;
- `day_entries` — дни календаря;
- RLS-политики, чтобы пользователь видел только своё, а admin/owner могли исправлять данные;
- Storage bucket `avatars`;
- RPC `email_for_username` для входа по username;
- триггер создания профиля после регистрации.

### Владелец сайта @rqndykss

Сначала зарегистрируйте аккаунт с username `@rqndykss`, затем один раз выполните:

```sql
update public.profiles
set role = 'owner'
where lower(username) = 'rqndykss';
```

Это безопаснее, чем автоматически выдавать права владельца любому новому аккаунту, который введёт такой username.

После этого @rqndykss сможет выдавать `Premium`, `admin` и `owner` другим пользователям.

## 3. Запуск

```bash
npm run dev
```

Откройте `http://localhost:3000`.

Для проверки TypeScript:

## Важные детали архитектуры

### Аккаунт и гость

При входе показывается выбор: войти в аккаунт или продолжить как гость. Гость хранит настройки локально. Авторизованный пользователь пишет данные в Supabase и может зайти с другого устройства.

### Аватары

Для аккаунта картинка загружается в `Storage → avatars`, затем публичный URL сохраняется в `profiles.avatar_url`.

### Отгулы

У доп. смены есть два режима:

- деньги — `extra_pay`, по умолчанию 3500 ₽;
- отгул — `extra_compensation = day_off`.

Использованный отгул отмечается как `offReason = compensatory`. Баланс считается автоматически.

### Исправление бага часов

Когда день превращается в отпуск/выходной, приложение сохраняет снимок предыдущей рабочей смены в `restoredWork`. При возврате в «Смена» часы/время восстанавливаются, а не остаются нулевыми.

## Рекомендуемые настройки Supabase Auth

Для быстрого теста можно временно отключить Confirm email в Authentication → Providers → Email. Для production лучше оставить подтверждение email включённым.

Для production также рекомендуется настроить SMTP/Resend, домен и политику паролей.
